---
typecheck: command that type-checks every package and exits non-zero on any error
lint: command that lints and format-checks the whole workspace and exits non-zero on any finding
test: command that runs the unit and golden tests and exits non-zero on any failure
test-integration: command that runs the integration tests against the database container used in CI (a read-only role) and exits non-zero on any failure
build: command that builds every package and app and exits non-zero on any error
bench: command that measures the budgeted numbers (context size in tokens per rendering level, bytes and rows read to build a data card, time to first card) and exits non-zero when any number is over its budget
contract-check: command that diffs the contract schemas against the last released version, replays the stored old Refs and compares the golden renderings; prints the schema diff and exits non-zero on an unintended break
security-test: command that runs the adversarial tests (write and escape attempts, canary secret, PII masking, injection-bearing data) and exits non-zero on any failure
repro-check: command that builds from a clean clone with the lockfile, resolves the golden Refs twice and exits non-zero unless the output is byte-identical
fixtures-gen: command that regenerates the test data files deterministically from the generator script
pack-dry-run: command that lists what each publishable package would contain, without publishing, and exits non-zero when a package would include a file outside its allow-list
smoke-install: command that installs the published packages into an empty directory from the registry, opens a generated fixture, resolves a Ref and lists the MCP tools, and exits non-zero on any failure
changeset: command that records a changeset (version bump level and note) for the current change
version: command that applies the pending changesets to package versions and changelogs
real-source-trial: command that runs the read-only trial against a real data source the user names (files or a database with a read-only role) and prints rows and bytes read, durations and any difference from the container run
publish-npm: wrapper command that publishes the publishable packages to the npm registry; takes --tag next or --tag latest
publish-ext: wrapper command that publishes the editor extension to the extension registry; takes --channel prerelease or --channel stable
push-tags: command that pushes the release commit and its version tags to the remote
make-public: command that changes the remote repository from private to public
pr-open: command that opens a pull request from the current branch against the trunk
pr-merge: command that merges the approved pull request into the trunk and deletes its branch
trunk: name of the default branch pull requests merge into
scratch: directory for throwaway exploration code and learning logs, ignored by version control
code: globs of the source and test files the build playbooks may edit (not the contract, fixtures, golden outputs or budgets)
contract: globs of the contract definitions (Ref grammar, protocol messages, MCP tool schemas, data card layout), the stored old Refs and the golden renderings; only contract changes edit them
refs-corpus: directory of stored Refs minted by earlier versions, which must keep resolving
fixtures: directory of generated test data files; regenerated by the fixtures command, never edited by hand
config: globs of workspace configuration the build playbooks may edit (manifests, lockfile, compiler and test configuration, changesets)
ci: globs of continuous integration workflow files
budgets: file holding the budgeted numbers read by the bench command
adr: directory of architecture decision records
docs: globs of documentation, changelog and release reports

# Bindings

Every value that changes from one repository to the next is a binding: commands, paths and globs, URLs, branch names, project keys, dashboards, thresholds of one service. Playbooks, the router and the principles write `${name}`; each project gives the value in `.flow/fusenduck-flow/project.md`. The skill itself names no repository, so it can be copied into any project of this kind.

A value is a string, or a list `[a, b]` (several globs or commands). The runtime fills the values in when it runs checks, guards commands and limits edits, and `flow status` shows them for the active playbook.
