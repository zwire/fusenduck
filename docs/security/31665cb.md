## What had no problem

- **The way to turn it off**: it can be turned off only by `--unmask` from the person who starts it (`fusen card|peek|resolve`, `fusen-mcp`). MCP tool arguments have no `unmask`, so an agent cannot turn it off by itself (existing test).
- **Hide before cutting**: the card hides first and then cuts at 40 characters, and rows are hidden first and then the cells are cut in rendering. A fragment of an email address left after cutting cannot slip through the shape check.
- **Logs and errors**: engine error messages are withheld and the log gets only the error kind (the fix in [acf8f0a](acf8f0a.md)). No exit for values that bypasses masking remains.
- **The duplicate note**: `AMBIGUOUS:` has only counts and contains no values.

## What remains by design (as #25 says)

- **Web UI and VS Code rows**: they are for the person on the spot to look at, so rows are not hidden. The card's min, max and avg are hidden. This is written in the docs (docs/guide.md).
- **Changing the shape with a query**: if `--query` renames things or breaks the shape of values, they cannot be found by column name or by shape. If the file's bytes are read as one string with `read_text`, hiding by column name does not work (hiding by shape does). A predicate is evaluated on the real values, so `email = '…'` can confirm a value. Masking is for display, not a guarantee. This sentence was added to docs/guide.md.
- **Phone numbers separated by spaces** (`03 1234 5678`) cannot be told apart from coordinates or lists of numbers, so they are not hidden.
- **The MAP key itself**: a key is hidden by shape (an email address as a key, for example). Whether the key's name indicates personal data is used only to hide the value.
- **Rewriting of hidden JSON**: when something inside JSON was hidden, the document is rewritten, so the way big integers and `1.0` in other fields are written can change. A document where nothing was hidden stays as it was.
- **Over-hiding**: a STRUCT or JSON object that has only `key` and `value` is treated as a MAP entry, and the value of `{"key": "phone", "value": …}` is hidden. In the card, if a string inside a nested value has a part like `phone:`, the whole bound is hidden. Neither shows too much.
- **Position of the note and order of rows**: `column N` is the order of the result's columns (DESCRIBE order). Rows are written as JSON objects, so a column name that looks like an integer (`"7"`) is sorted first, and the position can differ from the visual order. No values leak.
- **The header's source=** (from before): `source=` in the card's header line is the path run through `JSON.stringify`; newlines and quotes are escaped, but `>>>` goes in as it is. A folder name containing `<<<END_FUSEN_RESULT>>>` can make that string appear in the middle of the header line (it does not start a line). The path is given by the caller and is not file content.
