## 問題がなかったもの

- **外す手段**: 外せるのは起動する人の `--unmask`(`fusen card|peek|resolve`、`fusen-mcp`)だけ。MCP のツールの引数には `unmask` がなく、エージェントは自分で外せない(既存のテスト)。
- **切る前に伏せる**: カードは伏せてから 40 文字に切り、行は伏せてから描画でセルを切る。切った後のメールアドレスの断片が形をすり抜けることはない。
- **ログとエラー**: エンジンのエラー文は伏せ、ログにはエラーの種類だけを書く([acf8f0a](acf8f0a.md) の修正)。マスクを通らない値の出口は残っていない。
- **重複の注記**: `AMBIGUOUS:` は行数だけで、値を含まない。

## 設計として残っているもの(#25 が書いているとおり)

- **Web UI と VS Code の行**: その場にいる人が見るためのもので、行は伏せない。カードの min・max・avg は伏せる。文書(docs/guide.md)に書いてある。
- **クエリで形を変える**: `--query` で別名を付けたり値の形を崩したりすれば、列名でも形でも見つけられない。`read_text` でファイルのバイトを 1 つの文字列として読めば、列名による伏せ字は効かない(形による伏せ字は効く)。述語は本当の値で評価するので、`email = '…'` で値を確かめられる。マスクは表示のためのもので、保証ではない。この一文を docs/guide.md に足した。
- **空白で区切った電話番号**(`03 1234 5678`)は、座標や数の一覧と見分けられないので伏せない。
- **MAP のキーそのもの**: キーは形で伏せる(メールアドレスのキーなど)。キーの名前が個人情報を示すかどうかは、値を伏せるためだけに使う。
- **伏せた JSON の書き直し**: JSON の中で何かを伏せたときは、文書を書き直すので、ほかのフィールドの大きな整数や `1.0` の書き方は変わりうる。何も伏せなかった文書は元のまま。
- **伏せすぎ**: `key` と `value` だけを持つ STRUCT や JSON のオブジェクトは MAP のエントリと見なされ、`{"key": "phone", "value": …}` の値が伏せられる。カードでは、入れ子の値の中の文字列に `phone:` のような部分があると bound 全体を伏せる。どちらも見せすぎではない。
- **注記の位置と行の並び**: `column N` は結果の列の順(DESCRIBE の順)。行は JSON のオブジェクトとして書くので、整数のように見える列名(`"7"`)は先頭に並び、見た目の順と位置がずれることがある。値は漏れない。
- **ヘッダの source=**(以前から): カードのヘッダ行の `source=` はパスを `JSON.stringify` したもので、改行や引用符はエスケープされるが `>>>` はそのまま入る。`<<<END_FUSEN_RESULT>>>` を含むフォルダー名は、ヘッダ行の途中にその文字列を出せる(行頭にはならない)。パスは呼び出し側が渡すもので、ファイルの中身ではない。
