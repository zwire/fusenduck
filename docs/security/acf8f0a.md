## 問題がなかったもの

- **Web UI の入口**: 待ち受けはループバックの 3 つだけ。`Host` と `Origin` はサーバー自身の 3 つ以外 403(DNS リバインディング、別ページからの要求)。API は `application/json` の POST だけなので、別オリジンのページは単純な要求を作れない。`Origin: null` も 403。本文は 64KB まで。
- **引き換えコードとトークン**: コードは 32 バイトの乱数で、URL のフラグメントに載り(サーバーに送られない)、60 秒で切れ、1 回交換したら使えない。トークンは別の 32 バイトで、sha256 にそろえて `timingSafeEqual` で比べる。SPA は交換後に `history.replaceState` で URL からコードを消す。ブラウザーを開くコマンドの引数でコードが他のローカルユーザーに見えうる点は ADR 0002 のとおりで、先に使われた場合は利用者のページが「already used」になって気づける。
- **ファイル一覧**: シンボリックリンクをたどらず、隠しファイルを飛ばし、フォルダーの差し替えは読む前後の `realpath` で落とす。開くときは core がルートを改めて確かめる。
- **列と条件**: 条件は `checkPredicate`(1 つの単純な SELECT)と、表を読む関数・`*`・`COLUMNS(*)` の拒否を通ってから、鍵をかけたエンジンで動く。複文、`UNION` への脱出、`--` コメント、`LIMIT` は 400(既存テスト)。別ファイルを読む副問い合わせはエンジンが断り、ページには伏せた文言が返る(新しいテスト)。列名はファイルの列だけ。
- **#24 のエラー表示**: 見せるのは Parser/Binder/Catalog エラーの 1 行目だけ。DuckDB は「Candidate bindings」などの候補を 2 行目以降に書く。Ref の `where` で `read_csv` を使いファイルのバイトを CSV のヘッダとして読ませると、候補名がファイルのバイトになることを確かめたが、2 行目なので出ない。struct のキー、失敗する cast、JSON として読ませる形も合わせて回帰テストにした(`errors.test.ts` の 5 件、修正前から緑)。
- **秘密の漏れ(canary)**: 環境変数に canary を置き、Web UI の全 API と失敗 4 種(ルート外、別ファイル、`getenv`/`current_setting`、失敗する cast)を流した。どの応答にも出ない(新しいテスト)。`getenv` は Node の DuckDB にない。MCP の canary は既存のテストで緑。
- **画面への注入**: セルはすべて `textContent` で置き、CSP の `require-trusted-types-for 'script'` が `innerHTML` を拒む。e2e の悪意あるセル(`<img onerror>`、`</script>`)で何も実行されない(`pnpm test:e2e` 15 件緑)。
- **VS Code 拡張**: ホストはそのエディターのファイルしか開かず、クリップボードに置けるのは `parseRef` が通る文字列だけ。webview の CSP は nonce 付きのスクリプトだけを許し、`connect-src 'none'` で何も取りに行けない。ポートもトークンもない。
- **読み取り専用の守り**: `allowed_paths`、外部アクセスの禁止、`temp_directory=''`、`lock_configuration`。`pnpm test:security` の既存のケースはすべて緑。

## 残っているもの

- **FIFO の差し替え**: 確かめてから DuckDB が開くまでの間に、ファイルを FIFO に差し替えられる隙は残る。ルートに書ける相手が、確かめた直後に名前を差し替える必要がある。塞ぐにはファイルを自分で開いて渡す仕組みが要り、DuckDB の Node API にはない。
- **Web UI の切断と並列**: 接続が切れても走っているクエリは時計(10 秒)まで止まらず、`/api/open` を並べて送れば並べて開ける。どちらもトークンを持つページだけができることで、[e2399be](e2399be.md) のとおり今は入れていない。
- **束縛エラーに出る名前**: 1 行目に、ファイルの列名や struct のフィールド名が型の一部として出ることがある(`No function matches the given name and argument types '+(STRUCT("…" VARCHAR), INTEGER_LITERAL)'`)。名前はファイル由来の文字列だが、カードでも見えているもので、300 文字で切っている。エージェント向けの文言をデータの区切りに入れるかは、エラーの形を変える契約の話なので別に決める。
- **Ref の列名**: 選んだ列の名前は Ref の `cols=` に URL エンコードして入る。悪意ある列名はエージェントが読む Ref の文字列にも出る(以前からの Ref の形)。

## 未マージの PR を読んで気づいたこと

- **#25(PII マスク)**: マスクは MCP と CLI の出力(行とカード)にかかるが、Web UI と VS Code の行の表示(`View.rows`)にはかからず、カードの min/max にはかかる。画面の利用者は起動した本人なので行を見せるのは筋が通るが、カードと行で扱いが違うことを文書に書くとよい。また Ref の `query`/`where` で `read_text` を使えばファイルのバイトを 1 つの文字列として読めるので、列名によるマスクは通らない(値の形によるマスクはかかる)。PR が書いている「クエリで形を変えればすり抜ける」の一例。上の修正 2 で、ログからマスクを通らずに値が出る経路は閉じた。
- **#22(.vsix)**: `untrustedWorkspaces.supported: true` で、制限モードのワークスペースでも `.parquet` を開くと DuckDB がファイルを解析する。エンジンの鍵は読み書きの範囲を絞るが、パーサーそのものの不具合からは守らない。開くのは利用者の操作なので受け入れられる範囲だが、`limited` にして制限モードでは開く前に確認する手もある。DuckDB のネイティブモジュールを取りに行くときは `pnpm-lock.yaml` の integrity で確かめていて良い。
- **#23(Web UI の手触り)**: 新しい文言は列名の一覧と利用者自身の条件の文字列だけで、値は入らない。セルは `title` 属性にも置くが、属性なので実行はされない。問題なし。
